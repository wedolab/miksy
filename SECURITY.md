# Безопасность

## Как сообщить об уязвимости

Только закрыто — через GitHub: вкладка **Security** репо → **Report a vulnerability** (private
vulnerability reporting). Сообщение увидят только сопровождающие.

**Не заводите открытый issue** и не описывайте уязвимость в обсуждениях и pull request'ах.

Опишите, что нужно для воспроизведения (ОС, версия — `miksy --version`, шаги), и что получается. Не
прикладывайте настоящие секреты и конфиги агентов целиком — замените значения на `***`.

## Что считается уязвимостью

miksy работает с секретами и записывает настройки агентов, поэтому уязвимость — в том числе:

- утечка значений секретов из `local/` (`secrets.env`, `secrets/`, бэкапы) — в конфиги агентов, в
  git-репо проектов или конфигурации, в вывод команд, в файлы с открытым доступом;
- запись или удаление вне своих целей: в файлы, которые miksy не создавал и не должен трогать, по
  ссылкам за пределы дома или проекта, в файлы, отслеживаемые git;
- обход решения о доверии: запуск исполняемых настроек проекта (хуки, `.mcp.json`) без явного «да»
  пользователя;
- выполнение команд из содержимого конфигурации или репо проекта там, где miksy их только читает.

Ошибки, которые не дают таких последствий (неверный план, лишний конфликт), — обычный
[issue](https://github.com/wedolab/miksy/issues/new/choose).

## Поддерживаемые версии

Исправления выходят для последней версии (ветка `stable`). Обновление — `miksy update`.
