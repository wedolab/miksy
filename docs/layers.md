# Как устроены слои и куда miksy пишет

Из чего состоит конфигурация, в каком порядке проект получает слои, как убрать пришедшее сверху и какие файлы miksy
записывает каждому агенту. Сюда приходят, когда коротких слов из README мало.

## Что лежит в слое

Как выглядит конфигурация целиком (папки и файлы) — схема в «[Как устроен miksy](../README.md#как-устроен-miksy)».

### Порядок слоёв

**Дерево слоёв** (`layers/tree/`) повторяет workspace: проект получает слои по своему пути сверху вниз — `tree/`,
затем `tree/Acme/`, затем `tree/Acme/billing-api/`. Нет папки в дереве — нет слоя.

- **Правила** складываются: сначала верхних слоёв, внутри слоя — по имени файла (файлы с одним именем в разных
  слоях — оба).
- **MCP-сервер или skill** с тем же именем в нижнем слое заменяет верхний.
- **Регистр букв** в именах не важен: `Acme` и `acme` — один слой. Если в `layers/tree/` две папки отличаются только
  регистром (так бывает на Linux), применяется одна, и `miksy doctor` скажет какая.

Что получит проект и из какого слоя — `miksy explain <путь>` (без пути — текущий каталог; `--global` — домашние
настройки агентов). Папка вне workspace получает только домашние настройки — их `explain` и покажет.

### Содержимое слоя

Всё необязательно:

| Что | Зачем |
|---|---|
| `instructions/*.md` | правила — обычный markdown; склеиваются по порядку слоёв и по имени файла |
| `mcp/<имя>.yaml` | MCP-сервер («[Подключить MCP-сервер](../README.md#подключить-mcp-сервер)») |
| `skills/<имя>/SKILL.md` | skill («[Добавить свой skill](../README.md#добавить-свой-skill)») |
| `layer.yaml` | особые настройки слоя: `exclude`, `import_skills`, `trust`, `target`, `description` |

Эти имена заняты — так нельзя назвать организацию или проект (как и `hooks/` и `policies/`: их miksy не читает).

Убрать то, что пришло из слоя выше, — в `layer.yaml` нижнего слоя:

```yaml
exclude: [mcp.linear, skill.deploy, instructions.20-style.md]
```

### map.yaml: слой по шаблону и другое

Слой не по пути, а по шаблону — привязка в `map.yaml`: `layers: [{ match: "*/infra-*", use: infra }]`. Слой
`layers/infra/` получат все проекты, чьё место в дереве подходит под шаблон; он идёт после слоёв дерева и перекрывает
их. Место в дереве — путь от корня workspace, у проектов других корней — вместе с их веткой: проект
`E:/Clients/infra-x` корня с `tree: Clients` — это `Clients/infra-x` (шаблон `*/infra-*` подходит, `infra-*` — нет;
о ветках — «[Несколько корней workspace](roots.md#несколько-корней-workspace)»).

Ещё в `map.yaml`: `global` — какие слои домашние (по умолчанию `global` и `env-<ОС>`), `skill_prefix` — префикс ваших
skills, `tools` — программы, на которые ссылаются MCP-серверы слоёв (`${ИМЯ}`): мастер ищет их на машине и
записывает путь в `vars` файла `local/machine.yaml`, а не нашёл — подсказывает, как поставить. Примеры — в `map.yaml`
стартовой конфигурации.

## Куда miksy записывает настройки

В проект miksy пишет только файлы, которые git не отслеживает, и прячет их от git (`.git/info/exclude`) — в репо
проекта ничего не попадает. Файлы, которые закоммитила команда проекта, он не трогает никогда.

| Агент | Домашний каталог (действует везде) | В проекте |
|---|---|---|
| Claude Code | `~/.claude/CLAUDE.md`, MCP в `~/.claude.json`, `~/.claude/skills/` | `CLAUDE.local.md`, `.claude/skills/`, MCP проекта — в `~/.claude.json` |
| Codex | `~/.codex/AGENTS.md`, MCP в `~/.codex/config.toml`, `~/.agents/skills/` | `.codex/config.toml` (правила и MCP), `.agents/skills/` (или `.codex/skills/`) |
| opencode | `~/.config/opencode/AGENTS.md`, MCP в `opencode.json(c)`, `~/.config/opencode/skills/` | `opencode.json`, `.opencode/miksy.md`, `.opencode/skills/` |
| Antigravity | `~/.gemini/GEMINI.md`, MCP в `mcp_config.json`, `~/.gemini/config/skills/` | плагин `.agents/plugins/miksy/` (правила, skills, MCP) |

Полностью (запасные пути, скрипты в `local/run/`) — в `adapters/<агент>/CAPABILITIES.md`.

В общих файлах miksy меняет только своё: в файле правил — блок между `<!-- miksy:begin … -->` и `<!-- miksy:end -->`
(ваш текст вокруг остаётся), в общих конфигах агентов (`~/.claude.json`, `~/.codex/config.toml`, `opencode.json`,
`mcp_config.json`) — только свои ключи. Записанное miksy руками не правьте — меняйте слои: правка внутри его блока или
файла станет конфликтом.

## Учёт, бэкапы, оригиналы

**Учёт** (`local/state/manifest.json`, рядом копия `.bak`) — список того, что и с каким содержимым записал miksy. По
нему он отличает свои файлы от ваших и от правок руками.

**Бэкапы.** Перед изменением файла miksy кладёт его копию в `local/backups/<метка запуска>/`. Хранятся 20 последних
запусков; секреты в копиях заменены на `<secret:ИМЯ>`.

**Оригиналы.** Если miksy заменяет чужой файл (вы разрешили `--force` или содержимое совпало), он сохраняет оригинал
в `local/backups/originals/` — вне очереди удаления, со всеми значениями; `miksy clean` вернёт его на место.

Для разработчиков — [DESIGN §8.8–8.9](../DESIGN.md#88-учёт).
