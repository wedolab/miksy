# Если что-то пошло не так

Что значат сообщения miksy и что делать. Ищите по началу сообщения — оно в первой колонке.

← [README](../README.md)

Готовую команду с вашим путём miksy печатает в конце самого сообщения — выполните её как есть; здесь она не
повторяется. Не нашли ответа — [issue](https://github.com/wedolab/miksy/issues/new/choose) в репо движка (шаблон
подскажет, что приложить; вывод `miksy doctor` — без секретов).

Темы: [файлы, конфликты, учёт](#файлы-конфликты-учёт) · [секреты и MCP-серверы](#секреты-и-mcp-серверы) ·
[доверие](#сообщения-о-доверии) · [папки с проектами, корни, «забыть»](#папки-с-проектами-корни-забыть) ·

## Файлы, конфликты, учёт

«Цель» — проект или папка, куда miksy пишет настройки; «учёт» — его список записанного
([layers.md](layers.md#учёт-бэкапы-оригиналы)).

| Сообщение | Что значит и что делать |
|---|---|
| `КОНФЛИКТ … создан не miksy` | На месте файла — чужой. Проверьте; если его содержимое уже в слоях — `sync … --force` |
| `КОНФЛИКТ … изменён вручную` / `управляемый блок изменён вручную` | Перенесите ручную правку в слои, затем `--force` |
| `… отслеживается git-репо … — принадлежит команде` | Файл команды (или dotfiles) — miksy его не трогает, остальное агент получит |
| `каталог … версионирует команда` | Личные skills туда не кладутся. Codex возьмёт `.codex/skills`, если он не командный |
| `путь внутри вложенного git-репо` | Это submodule — miksy туда не пишет |
| `каталоги hooks/ и policies/ miksy не читает` | Хуки и права через miksy не настраиваются |
| `файл занят другим процессом … его держит <программа> (PID …)` | Закройте программу и повторите `sync`; файл не изменён |
| `ВНИМАНИЕ: часть ключей пропала` / `ключи пропали` (doctor) / `изменился после планирования` / `план пересчитан` | Сессия агента переписала конфиг во время sync. Закройте сессии, повторите `sync` |
| `путь вне …` / `… через симлинк … — вне …` | Ссылка за пределы дома/проекта — miksy туда не пишет |
| `симлинк указывает на несуществующий файл` | Почините ссылку на конфиг агента |
| `сбой git: …` | Проверьте `git status` в проекте |
| `файл не разбирается как JSON` | Исправьте конфиг агента; остальное синхронизировано |
| `уже принадлежит цели …` | Ваша ссылка каталогов: два агента пишут один файл. Уберите её |
| `хеш неизвестен` | Две копии проекта стали одной. Проверьте файл; верный — `sync … --force` |
| `учёт повреждён или недоступен` | Восстановите `local/state/manifest.json` из `manifest.json.bak` рядом |
| `каталог не пуст и не песочница miksy` | Для `--out` укажите новый или пустой каталог |
| `Конфликты первого sync` (doctor) | Решите, как `КОНФЛИКТ` выше |
| Claude не видит MCP-серверы проекта (сообщения miksy нет) | miksy записал их под настоящим путём папки (без ссылок, с регистром букв как на диске). Проект открыт по другому пути (симлинк, другой регистр) — откройте по настоящему или повторите `sync` |
| `Учёт miksy перенесён вслед за каталогами` (sync) / `Каталоги переехали` (doctor) | Каталог переехал ([README](../README.md#переименовали-или-перенесли-каталог)). Ничего не нужно |
| `Учёт ссылается на несуществующие каталоги` (doctor) | `miksy clean <прежний путь>` уберёт записанное и запись |
| Агент не видит изменений | Перезапустите сессию агента |

## Секреты и MCP-серверы

| Сообщение | Что значит и что делать |
|---|---|
| macOS: MCP-сервер с `npx`/`uvx` в графической программе (Zed, IDE Antigravity, Codex Desktop) — `Connection closed`, а в терминале работает | Из Dock/Finder PATH без Homebrew. В `vars` (`local/machine.yaml`): `NPX: /opt/homebrew/bin/npx` (из `which npx`), `BREW_BIN: /opt/homebrew/bin`; в слое: `command: ${NPX}`, `env: { PATH: "${BREW_BIN}:/usr/bin:/bin" }`; `sync`. Или запускайте программу из терминала |
| `пропущен сервер … — не заданы переменные` | Допишите в `local/secrets.env` или `vars` |
| `многострочное значение секрета` / `… длиннее 1023 байт` / `… содержит "` | Такое значение не доставить; сервер пропущен, значение никуда не записано |
| `секрет … в command` / `в agents.….raw не поддерживается` | Только через `env`, `args`, `headers`, `url` |
| `секрет … в env HTTP-сервера … не доставляется` | Перенесите секрет в `headers` |
| `секрет передаётся аргументом` | Виден в списке процессов — перенесите в `env`, если сервер умеет |
| `секрет ИМЯ короче 4 символов` | Проверьте, секрет ли это |
| `секрет … пустой в local/secrets.env` | Задайте секрет (на Windows сервер через `.cmd` пустое значение вообще не получит — переменной не будет) |
| `секреты открытым текстом в слоях` | Уйдёт в git. Значение — в `local/secrets.env`, в слое — `${ИМЯ}` |
| `… вне учёта, а в нём значение секрета` / `Значение секрета в ключе вне учёта` (doctor) | Сервер miksy — `sync <цель> --agent <агент> --force`; глобальный Codex — `adopt` |
| `Значения секретов в конфигах агентов` (doctor) | `sync` заменит серверы обёртками |
| `Файлы секретов: нет файла / лишний / устарел / доступ не только у владельца` (doctor) | `sync` исправит; «не от miksy» — справочно |
| `… ссылка на …: … закройте вручную (PowerShell): <команда>` / `битая ссылка внутри local/` | Ссылка в `local/` (например, `local/secrets` на другом диске) ведёт туда, где доступ есть не только у вас, или никуда («цель ссылки» в сообщении — куда она ведёт, не цель miksy). Открыта — выполните команду из конца строки, затем `miksy sync --global` и `--all`; проверка — `miksy doctor`: строки больше нет. Битая — исправьте ссылку или удалите её (саму ссылку, не то, куда она ведёт). Ссылки в копии «до miksy» (`local/backups/before-miksy-…`) не трогайте: они ведут к вашим dotfiles, miksy их не проверяет |
| `… ссылка на …: … miksy не пишет туда бэкапы и копии ваших файлов` (команды, которые пишут, и doctor) | `local/backups` или что-то в нём — ссылка на открытую другим или пропавшую папку; ничего не записано. Обычно — команда из строки. Папка должна остаться открытой, диска нет или ссылка внутри `originals` — [замените её папкой](#заменить-ссылку-в-localbackups-папкой). Затем повторите команду. `… Закройте папку бэкапов …`, `ОШИБКА (цель синхронизирована частично)` — команда из строки |
| `Небезопасные права` … `доступ есть не только у владельца` (doctor; путь в `local/`, не ссылка) | `miksy sync --global` закроет их |
| `Нет исполняемого файла обёртки` (doctor) | Программа сервера сменила путь: поправьте `command` в слое или `sync` |
| `… убран из конфига opencode (с {file:} …)` | Задайте секрет и повторите `sync` |
| `miksy bridge: … редиректом` | Мост miksy к HTTP-серверу не следует редиректам. Укажите конечный `url` |
| `miksy bridge: … GET-потоку` / `… не ответил за … с` / `… закрыл ответ` | GET-поток не поддерживается, сервер молчал 10 минут или оборвал ответ |
| `miksy bridge: HTTP 401 …` | Проверьте токен в `local/secrets.env`, затем `sync` |
| Сервер с секретом «Connection closed» в агенте | `miksy doctor`; запуск обёртки из `local/run/…` вручную покажет причину |

### Заменить ссылку в local/backups папкой

«Цель ссылки» здесь — папка, куда ведёт ссылка `local/backups` (на другом диске и т. п.), а не цель miksy (проект,
куда он пишет настройки).

Скопируйте цель ссылки рядом, уберите саму ссылку, переименуйте копию (ссылку на файл — так же). Ссылка не убралась —
переименование откажет, ничего не испортив. Диска с целью ссылки нет — копировать нечего: только уберите ссылку
(вторая строка), miksy создаст обычную папку сам.

```powershell
Copy-Item -Recurse -LiteralPath '<цель ссылки>' -Destination '<ссылка>.new'
(Get-Item -LiteralPath '<ссылка>' -Force).Delete()
Rename-Item -LiteralPath '<ссылка>.new' -NewName '<имя ссылки>'
```

```sh
cp -R '<цель ссылки>' '<ссылка>.new' && rm '<ссылка>' && mv '<ссылка>.new' '<ссылка>'
```

Windows: есть в цели ссылки папка `before-miksy-…` — заменять нельзя: копия превратит её ссылки на ваши dotfiles в файлы, и
[возврат копии «до miksy»](uninstall.md#3-вернуть-копию-до-miksy) затёр бы нынешние. Тогда только закройте цель ссылки
командой из строки отказа.

Прежнюю цель ссылки после замены не удаляйте, а если она была открыта — закройте: в ней копии ваших файлов. miksy о ней уже
не знает и команду не напечатает:

```
icacls '<цель ссылки>' /reset; icacls '<цель ссылки>' /inheritance:r /grant:r '*<ваш SID>:(OI)(CI)F'   # Windows (PowerShell); свой SID — whoami /user
chmod 700 '<цель ссылки>'                                                                       # macOS, Linux
```

Цель ссылки — файл: в команде Windows `:F` вместо `:(OI)(CI)F`, на macOS и Linux — `chmod 600`. Команда Windows оставляет
доступ только вам — снимает и записи SYSTEM и «Администраторов».

## Сообщения о доверии

Что это и как решать — [trust.md](trust.md).

| Сообщение | Что значит и что делать |
|---|---|
| `Нужно решение пользователя о доверии` (sync, doctor) | В проекте исполняемые настройки не от miksy (хуки, `.mcp.json`, чужой `.codex/config.toml`, ответы в окне Claude). `miksy trust <проект>` в терминале; для организации — `trust` в слое. Агенту — не подтверждать самому |
| Серверы `.mcp.json` в Claude — `Pending approval` | `miksy trust <проект>` (или `trust: true` в слое) |
| `Claude: проект не доверенный — headersHelper …` | HTTP-сервер с секретом получит 401. Причина — в строке «нет доверия» |
| `Исполняемые настройки в подкаталогах групп без git` (doctor) | Удалите их, сделайте каталог git-репо или запретите доверие группы |
| `проект не доверенный в Claude: одобрение серверов .mcp.json (…) снимается` (sync, doctor) | Вы сняли доверие в окне Claude. Доверитесь снова — `sync` вернёт одобрение |
| `… доверие не меняется — запрет trust: { claude: false } в …` / `… доверие не ставится — запрет …` / `… доверие не меняется` (trust) | Снимите запрет (место — в сообщении), затем `miksy sync` |

## Папки с проектами, корни, «забыть»

«Корень» — папка с проектами, «забыть» — убрать из учёта записи об отключённом диске ([roots.md](roots.md)).

| Сообщение | Что значит и что делать |
|---|---|
| `взять под учёт … файл miksy (блок miksy), которого не было в учёте` (sync) | После «забыть» файл взят обратно (так же бывает в облачной папке, куда писал miksy другой машины). Ничего не нужно |
| `КОНФЛИКТ … файл miksy (блок miksy), которого нет в учёте, отличается …` | Слои поменялись после «забыть»: `sync … --force` (прежний — в бэкап). Облачная папка — [roots.md](roots.md#одна-облачная-папка-на-двух-машинах) |
| `удалить … (файл miksy, которого не было в учёте, — больше не нужен)`, `убрать только блок — блок miksy, которого не было в учёте, больше не нужен` (sync, clean) | miksy убирает ненужное, прежнее — в бэкап. Ничего не нужно |
| `одобрение .mcp.json … взять под учёт — одобрения miksy, которых не было в учёте` (sync) | Ничего не нужно |
| `Записанное в … забыто. Если диск найдётся: …` (clean, root remove) | Диск вернётся — команды из сообщения ([roots.md](roots.md#диск-нашёлся-после-забыть)). Ваши прежние файлы miksy не вернёт — берите из `local/backups/originals/`. Где miksy только дописал блок, копию «до блока» не возвращайте — потеряете дописанное |
| `группа X выше не получила правила Claude` | `miksy sync X`, затем `sync` цели |
| `пометка группы … снята, а её файлы остались` | `miksy sync --all` |
| `не git-репо — настроек не получат (N): …` (sync --all) / `Каталоги без git на уровне проектов` (doctor) | Нужны настройки — `git init` или `miksy target <путь>` ([README](../README.md#папка-без-git-заметки-выгрузки-группа-проектов)) |
| `новых целей: … подтвердите: --yes` | Проверьте план (`--dry-run`), затем `--yes` |
| `нет доступа (права каталога)` / `пропущен при поиске проектов` | Проекты в этом каталоге не видны, остальное работает |
| `Похоже на опечатку или переименование` (doctor) | Переименуйте каталог слоя в `layers/tree/` |
| `Каталоги слоёв отличаются только регистром` (doctor) | Соберите файлы в одну папку, остальные удалите, `miksy sync --all` |
| `Ветки дерева слоёв без папки на этой машине, но с похожей папкой` (doctor, справочно) | Ветка другой машины — ничего; опечатка — переименуйте |
| `… — git-репо / проект корня … / папка внутри git-репо … / папка внутри проекта …: корнем workspace он станет папкой с проектами, а не проектом` (root add, мастер) | Корнем добавьте папку, где лежит репо (команда — в сообщении). Нужен именно такой — `--yes` |
| `… — теперь корень workspace (папка с проектами), а не проект` (sync --all, doctor) | По ошибке — `miksy root remove "<путь>"`; так задумано — `miksy clean "<путь>"`. Была там папка без git с пометкой `target: true` — пометка перестаёт действовать, записанное туда `sync --all` убирает сам |
| `… — основной корень workspace (папка с проектами), а не проект` (sync --all, doctor) | Убрать записанное — `miksy clean "<путь>"` |
| `Слои, которые на этой машине ни к чему не применяются` (doctor) | Нормально |
| `Части дерева слоёв, которых нет на этой машине` (doctor) | Ветки других машин. Нормально |
| `корень … указан дважды (… — один и тот же каталог: повтор, junction или симлинк)` | Оставьте одну запись в `local/machine.yaml` |
| `tree «…» корня …` / `workspace — путь или список корней` | `tree` — имена через `/` без `..`; элемент — путь или `{ path, tree }` |
| `у корня … не указана ветка дерева слоёв` / `tree: … уже у корня …` | Каждому дополнительному корню — своя `tree` ([roots.md](roots.md#правила-нескольких-корней)) |
| `ветка layers/tree/… корня … совпадает с папкой … корня …` | Смените `tree` или переименуйте папку; общее — слоем в `map.yaml` |
| `корень … недоступен (нет диска / ссылка ведёт в никуда / каталога нет / пуст …)` | Ничего не тронуто. Подключите диск или `miksy root remove <путь>` ([roots.md](roots.md#корень-недоступен)) |
| `На недоступном диске осталось записанное miksy — N файлов в …` (clean) | Подключите диск и повторите; данных нет — `--forget` |
| `Проект был забыт … Skills, плагин Antigravity и opencode.json от miksy могут остаться` / `Остались файлы агентов, которых нет в agents …` (clean) | Строки из сообщения — по порядку. Папка вне workspace — сначала [верните корень](#вернуть-корень-забытого-проекта) |
| `Папки … нет (она вне workspace / её корень недоступен): записанного туда учёт не помнит, осталась только отметка «проект забыт»` (clean) | Вернётся — `miksy clean "<путь>"`; нет — с `--forget` |
| `Корень … недоступен: в его проектах осталось записанное miksy …` (clean --all) | Подключите диск и повторите; данных нет — команды из сообщения |
| `Каталога … нет: диск не подключён или данных больше нет? Забыть записанное туда?` | «Нет» — записи ждут диска; «да» — забыть |
| `Корень … недоступен и лежит внутри корня …: … Корень не убран` (root remove) | Подключите диск или `--forget` |
| `Учёт целей недоступного корня … не проверяется` (doctor) | Диск вернётся — `miksy clean "<путь>"`; нет — с `--forget` |
| `Учёт целей вне workspace без каталога … каталога нет: диск не подключён или папку удалили` (doctor) | Диск вернётся — подключите и `miksy clean "<путь>"`; папки больше нет — то же, на «забыть?» — «да» (без терминала — с `--forget`) |
| `Ветки корней внутри чужих мест` (doctor), `справка: … лежит внутри места …` (root add) | Не задумано — вынесите ветку; общее — слоем в `map.yaml` |
| `… — служебный каталог miksy` (sync, explain без пути) | Запустите в каталоге проекта или укажите путь |
| `… — основной корень, его нельзя убрать` (root remove) | [Сменить основной корень](roots.md#сменить-основной-корень) |
| `Цели учёта вне workspace` (doctor) | Убрать — `miksy clean <путь>`; нужны — `miksy root add` |
| `корень … лежит внутри проекта …` / `… внутри группы …` | Перенесите каталог или уберите корень |
| `… — корень workspace, а не проект` / `… — не проект: каталог без git и не цель` / `… — каталог вне workspace` (sync) | Все проекты — `sync --all`, домашние — `--global`, другой — `sync <путь>`; без git — `git init` или `miksy target`; папка с проектами — `miksy root add .` |
| `… — каталог без git и не цель: sync --all его не обновит` (sync <путь>) | Записано разово: `sync --all` и `doctor` такой каталог не видят. Нужен постоянно — `miksy target <путь>` или `git init` |
| `clean убирает записанное — только явно` | Укажите путь, `--global` или `--all` |
| `Проект забыт` (doctor) | `miksy sync <путь>`; файлы не нужны — затем `miksy clean <путь>` |
| `Учёт агентов, которых нет в agents` (doctor, справочно) | Команды из сообщения или верните агента в `agents` |

### Вернуть корень забытого проекта

`miksy root add` — с корнем, где лежала папка: путь и ветку печатал `root remove` («Убрать корень <путь> →
layers/tree/<ветка>»), они же — в копии `local/machine.yaml`. На «Записать настройки проектам workspace сейчас?» —
«нет». После `clean` уберите корень (`root remove`; «Убрать записанное…» — «нет»).

Основной корень, смененный `setup --force`: путь — прежний основной, ветка — любая новая, которой ещё нет в
`layers/tree`. Слои его проектов **скопируйте** под неё, не переносите: ветки у него не было — `layers/tree/<папка>` →
`layers/tree/<ветка>/<папка>`; была — всё содержимое `layers/tree/<прежняя ветка>` → `layers/tree/<ветка>`. К
привязкам его папок в `map.yaml` допишите такие же с новой веткой в начале, прежние не трогайте. После — удалите
копию и дописанные привязки. Вернуть его насовсем, со слоями, — «[Вернуть прежний основной дополнительным корнем](roots.md#вернуть-прежний-основной-дополнительным-корнем)».

## Установка, окружение, обновление

| Сообщение | Что значит и что делать |
|---|---|
| `… установок несколько — используется …` (doctor, setup, install) | Удалите лишнюю. Для Bun затем `miksy setup`, `miksy sync --global` и `sync --all` |
| `CODEX_HOME=…` / `CLAUDE_CONFIG_DIR=…` / `XDG_CONFIG_HOME=…`: `… настройки miksy агент не увидит` (doctor) | Уберите переменную из профиля оболочки |
| `Прежнее имя агента … gemini теперь antigravity` (doctor) | Переименуйте, когда удобно |
| `opencode … — версия 1.x, а miksy пишет настройки в формате opencode 2.x` (doctor, setup) | Обновите opencode ([install.md](install.md#установка-агентов)) |
| `в движке есть незакоммиченные правки` (update) | `git -C <движок> stash`, затем `miksy update` |
| `ветка … движка разошлась с …` / `локальная ветка stable разошлась с …` (update) | Команды из сообщения сохранят ваши коммиты |
| `… Нет доступа к репо` (update) | Сеть (прокси, VPN) или вход: `gh auth login`, `gh auth setup-git` |
| `движок не на ветке (… detached HEAD)` / `движок на ветке …` (update) | `git -C <движок> checkout stable`, затем `miksy update` |
| `учёт miksy … записан более новой версией движка` (sync, doctor) | Другая копия движка новее — `miksy update`; откатились — [update.md](update.md#откатиться-на-прежнюю-версию) |
| `неизвестные ключи — miksy их не читает` (sync, doctor) | Опечатка или ключ новой версии (`miksy update`) |
