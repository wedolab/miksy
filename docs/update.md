# Обновление и откат

Как поставить новую версию miksy, как вернуть прежнюю, если новая мешает, и что учесть при переходе между версиями.

← [README](../README.md)

## Обновление miksy

```
miksy --version          # какая версия стоит
miksy update --check     # есть ли новая (ничего не меняет и не скачивает)
miksy update             # что изменилось — и после «y» обновить
```

Номер нынешней версии (`miksy --version`) перед обновлением запишите — он понадобится, если захотите откатиться.

`miksy update` берёт новую версию из ветки `stable` (на ней — последний выпуск) и сначала показывает записи
[CHANGELOG.md](../CHANGELOG.md) между вашей версией и новой. Отдельно выделено **«Ломает»** (что будет работать иначе)
и **«После обновления»** (что запустить или поправить в конфигурации). После «y»:

1. обновляет движок (папку с программой miksy) — только «вперёд» (`git merge --ff-only`): ничего не перезаписывает и
   не удаляет;
2. уже новой версией: безопасная часть `setup` (команда `miksy`, `local/`), `doctor` и сводка того, что изменят у
   агентов `sync --global` и `sync --all`;
3. спрашивает «Записать настройки агентам?» — `sync --global` и `sync --all`. Затем перезапустите сессии агентов.

Файлы, которые miksy пишет в папку движка (`CLAUDE.local.md` и т. п.), спрятаны от git — обновлению не мешают.

**Убирали агента из `agents`?** Шаг 2 (как и `miksy setup --yes`, в том числе при откате) дописывает в `agents` всех
агентов, найденных на машине («✓ в local/machine.yaml добавлены агенты: …»). На «Записать настройки агентам?» тогда
ответьте «n», снова уберите агента из `agents` в `local/machine.yaml` и только потом `miksy sync --global` и
`miksy sync --all` — иначе `sync` снова запишет ему настройки.

Без терминала (скрипт, агент) — обновление только с `--yes`, настройки агентам `update` не пишет: печатает команды
`sync`.

**Откажет и объяснит**, если в движке есть свои правки (не правьте и не коммитьте файлы движка — всё своё живёт в
конфигурации), в ветке свои коммиты или движок скачан не через git.

**Вы на ветке `main`** (клонировали до появления выпусков) — `miksy update` предложит перейти на `stable`.

## Откатиться на прежнюю версию

Новая версия мешает — верните прежнюю. Здесь описан откат не ниже 0.2.1: старым версиям нужна подготовка, её
описание осталось только в истории git движка. Понадобятся:

- **`<каталог движка>`** — папка, куда вы скачали miksy (например, `~/Projects/miksy`); путь показывает
  `miksy explain` (строка «Движок miksy …»);
- **номер прежней версии** — тот, что вы записали перед обновлением. `update` печатал его и сам: «движок обновлён:
  0.2.2 → 0.2.3» — прежняя первая; в команде она с буквой `v` — `v0.2.2`. Вывод не сохранился — спросите git, на
  каком выпуске ветка `stable` была до последнего обновления (кавычки нужны в PowerShell):

  ```
  git -C "$HOME\Projects\miksy" describe --tags 'stable@{1}'     # Windows (PowerShell), движок в $HOME\Projects\miksy
  git -C ~/Projects/miksy describe --tags 'stable@{1}'            # macOS, Linux
  ```

  Ответ — номер прежней версии. Нужна ещё более ранняя — `'stable@{2}'`, `'stable@{3}'`. Git ответил ошибкой:
  - `log for 'stable' only has 1 entries` — до последнего `update` движок был на ветке `main`: вместо первой команды
    ниже — `git -C <каталог движка> checkout main`, затем остальные три;
  - `not a git repository` или `cannot change to …` — неверен путь (проверьте в `miksy explain`) или движок скачан
    не через git — тогда скачайте нужный выпуск заново ([Установка](../README.md#установка));
  - `log for refs/heads/stable is empty` — обновлялись больше 90 дней назад; список выпусков — `git -C <каталог
    движка> tag --sort=-v:refname` (сверху новые): по [CHANGELOG.md](../CHANGELOG.md) возьмите выпуск под тем, с
    которого началось то, что мешает; не знаете — сразу под нынешним, не помогло — ещё на один ниже (не ниже
    `v0.2.1`).

Команды отката (только Windows, откат на 0.2.1, и в `local/` есть ссылки — например, `local/secrets` на другом диске:
до них шаги «до отката» из «[Windows: откат на 0.2.1…](#windows-откат-на-021-когда-в-local-есть-ссылки)», иначе
0.2.1 сбросит права ваших dotfiles):

```
git -C <каталог движка> checkout -B stable v0.2.2
miksy setup --yes
miksy sync --global
miksy sync --all
```

Например, движок в `$HOME\Projects\miksy` (Windows, PowerShell) или `~/Projects/miksy` (macOS, Linux):

```
git -C "$HOME\Projects\miksy" checkout -B stable v0.2.2      # Windows (PowerShell)
git -C ~/Projects/miksy checkout -B stable v0.2.2               # macOS, Linux
```

- `checkout -B stable v0.2.2` ставит ветку `stable` на прежний выпуск. Незакоммиченные правки в файлах движка не
  теряются: если мешают, git откажет; не нужны — `git -C <каталог движка> stash` и команду ещё раз. Следующий
  `miksy update` снова предложит новую версию — чтобы остаться на прежней, отвечайте «n»;
- `miksy setup --yes` — уже прежней версией обновит под неё команду `miksy` и `local/`. Убирали агента из `agents` —
  она допишет его снова: уберите его ещё раз до `sync`;
- `sync --global` и `sync --all` перепишут настройки агентов так, как их пишет прежняя версия.

Проверка: `miksy --version` — прежний номер; `miksy doctor` — без ошибок. Вернуться на новую версию — `miksy update`
([Обновление miksy](#обновление-miksy)). Если после отката или возврата `sync` спросит о доверии
Claude проекту, где вы отвечали Claude «да, больше не спрашивать», и в вопросе только ваши ответы в окне Claude —
ответьте «да» (в терминале или `miksy trust "<путь проекта>"`).

Если по разделу «После обновления» новой версии вы что-то меняли в конфигурации (например, переименовали агента в
`local/machine.yaml`) — верните, как было. И напишите в [issue](https://github.com/wedolab/miksy/issues/new/choose),
что пошло не так.

**Сообщение «учёт … записан более новой версией движка»** после отката — если шаги выше сделаны, всё работает. Учёт
(`local/state/manifest.json` — список того, что miksy записал) последней писала новая версия. Откатились на 0.2.2 или
новее — сообщение убирает `miksy setup --yes` (если команда `miksy` ведёт на этот движок). На 0.2.1 оно
остаётся до первого `sync` или `clean`, который что-то изменит, или до возврата на новую версию.

## Особенности версий

**С 0.2.1 на 0.2.2 (обновление)** — обычно ничего делать не нужно. Если `local/backups` — ваша ссылка на папку на
другом томе, открытую другим или несуществующую, пишущие команды остановятся в начале, ничего не записав; в строке
отказа — что сделать ([Если что-то пошло не так](troubleshooting.md#секреты-и-mcp-серверы), строка «… miksy не пишет
туда бэкапы»). То же на Windows, если ссылка ведёт на папку, закрытую только для вас без наследования прав, и 0.2.1
оставила в ней папки без доступа даже для вас: одна готовая команда в строке отказа.

**С 0.2.2 на 0.2.1** — команды отката выше; на Windows — ещё шаги до и после них (ниже). Сообщение «учёт … записан
более новой версией движка» останется до первого `sync` или `clean` с изменениями.

### Windows: откат на 0.2.1, когда в local/ есть ссылки

Прежние версии проверяют права `local/` сквозь ссылки: если за ссылкой что-то открыто другим, каждая их команда падает
с «local/ не закрыт» и сбрасывает права файлов за ссылкой — ваших dotfiles. Ссылки бывают: в копии «до miksy»
(мастер копирует ваши настройки агентов ссылками, если они — ссылки на папку dotfiles) и `local/secrets`,
`local/backups` или сама `local`, если вы перенесли их на другой том. Не знаете, есть ли они, — сделайте шаги всё
равно: без ссылок шаг 1 ничего не меняет, шаг 2 выносит копию «до miksy» рядом с конфигурацией, шаг 5 её вернёт.
Останетесь на прежней версии — копия так и лежит рядом (путь печатает шаг 2: «вынесена: …»); его подставьте в команду
возврата из [Как удалить miksy](uninstall.md#3-вернуть-копию-до-miksy). Ссылки `local/secrets`, `local/backups` заменять папками не нужно,
если их цели закрыты так, как закрывает miksy.

Все команды — в одном окне PowerShell, по порядку. Сначала пути: в первой строке — ваша папка конфигурации (например,
`C:\Users\you\Projects\miksy-config`; кавычку в пути — `'`, `’`, `‘` — удвойте), остальные — как есть:

```
$c = [IO.Path]::GetFullPath('<конфигурация>').TrimEnd('\')
function T($p) { $i = Get-Item -LiteralPath $p -Force -ErrorAction SilentlyContinue; if ($i -and $i.Target) { $t = @($i.Target)[0]; if (-not [IO.Path]::IsPathRooted($t)) { $t = Join-Path (Split-Path $p) $t }; [IO.Path]::GetFullPath($t).TrimEnd('\') } }
$l = T "$c\local"; $d = if ($l) { $l } else { $c }; if (-not $l) { $l = "$c\local" }
$b = T "$l\backups"; if ($b) { $d = $b } else { $b = "$l\backups" }; $s = T "$l\secrets"
```

`$l` — папка `local` (или цель ссылки `local`), `$b` — папка бэкапов (или цель ссылки `local/backups`), `$s` — цель
ссылки `local/secrets`, если это ссылка.

1. **Закройте цели ссылок так, как закрывает miksy** — даже если они уже закрыты. Цель, закрытую вручную записью
   `<вы>:F` без `(OI)(CI)`, прежняя версия сломает: её новые папки там не получат вашего доступа. Команда оставляет
   доступ только вам, с `(OI)(CI)` (наследуется всем внутри); ссылки внутри не трогает:

   ```
   $me = [Security.Principal.WindowsIdentity]::GetCurrent().User.Value
   function Reset-MiksyTree($p) { Get-ChildItem -LiteralPath $p -Force | Where-Object { -not ($_.Attributes -band 1024) } | ForEach-Object { icacls $_.FullName /reset /q | Out-Null; if ($_.PSIsContainer) { Reset-MiksyTree $_.FullName } } }
   $all = @(); if ($l -ne "$c\local") { $all += $l }; if ($b -ne "$l\backups") { $all += $b }; if ($s) { $all += $s }
   foreach ($t in $all) { if (-not (Test-Path -LiteralPath $t)) { "битая ссылка, цели нет: $t"; continue }; icacls $t /reset | Out-Null; icacls $t /inheritance:r /grant:r "*${me}:(OI)(CI)F" | Out-Null; Reset-MiksyTree $t; "закрыта: $t" }
   ```

   Ссылок нет — ничего не печатает. «битая ссылка, цели нет» — исправьте ссылку или замените её обычной папкой
   (`doctor` скажет как) и повторите шаг: с битой ссылкой прежняя версия падает на каждой команде. Проверка:
   `miksy doctor` — без строк «закройте вручную», «битая ссылка» и «miksy не пишет туда бэкапы».
2. **Вынесите копию «до miksy»** из `local/` (и из цели `local/backups`) — рядом, на тот же диск. Команда только
   переименовывает папку, ссылки в ней остаются ссылками; на другой диск она откажет, ничего не тронув. `Move-Item`
   не используйте: он переносил бы сквозь ссылки и удалял бы ваши файлы.

   ```
   if ($d -match '^[A-Za-z]:$') { "цель ссылки — корень диска ${d}\: вынести копию некуда" } elseif (Test-Path -LiteralPath $b) { Get-ChildItem -LiteralPath $b -Force -Filter 'before-miksy-*' | ForEach-Object { [IO.Directory]::Move($_.FullName, "$d-$($_.Name)"); "вынесена: $d-$($_.Name)" } }
   ```

   Копии (или папки `local\backups`) нет — ничего не печатает. Вынесенная копия — не проект: `sync` её не трогает.
   «цель ссылки — корень диска» — вынести копию некуда: с такой ссылкой откат на Windows не поддерживается.
3. **Проверьте, что других ссылок не осталось** — до первой команды прежней версии. Команда печатает каждую ссылку на
   папку в `local/` и целях ссылок, кроме самих `local\backups` и `local\secrets`. Ссылки на файлы (например,
   `local\secrets.env`) не показывает: прежние версии в них не заходят — их не трогайте.

   ```
   function L($p) { Get-ChildItem -LiteralPath $p -Force | ForEach-Object { if ($_.Attributes -band 1024) { if ($_.PSIsContainer) { $_.FullName } } elseif ($_.PSIsContainer) { L $_.FullName } } }
   @(L $l; if ($s) { L $s }; if ($b -ne "$l\backups") { L $b }) | Where-Object { $_ -notin "$l\backups", "$l\secrets" }
   ```

   Пусто — можно откатываться. Путь внутри папки `before-miksy-…` — копия «до miksy» не вынесена: сначала шаг 2,
   затем проверку снова (такие ссылки по одной не выносите). Другой путь — ваша ссылка (например, папка внутри
   `local\backups`, которую вы сделали ссылкой): прежняя версия сбросит права за ней. Вынесите её туда же, куда шаг 2:
   `[IO.Directory]::Move('<путь из проверки>', "$d-<имя ссылки>")`, если путь начинается с `$b`; иначе —
   `"$c-<имя ссылки>"` (если сама `local` — ссылка, — `"$l-<имя ссылки>"`). После шага 5 верните так же, поменяв пути
   местами (пока она вынесена, `clean` прежней версии не вернёт оригиналы из неё). Или не откатывайтесь: с такой
   ссылкой откат на Windows не поддерживается.
4. **Команды отката** ([выше](#откатиться-на-прежнюю-версию)). Проверка: `miksy --version` — прежняя версия;
   `setup --yes` и `sync` — без «local/ не закрыт» и «icacls не закрыл». Появилась такая строка — больше команд
   прежней версии не запускайте: вернитесь на новую версию (команды отката с её номером, затем шаг 5) и запустите `miksy doctor`. Строка с готовой командой в конце
   («закройте вручную (PowerShell): …», «Закройте папку бэкапов и всё в ней (PowerShell): …») — выполните её: так
   чинится и пропущенный шаг 1. Затем шаги 1–3 снова и проверьте права за ссылками: `icacls '<цель ссылки>' /T` —
   под каждым путём видно, у кого доступ. Чужой — `BUILTIN\Users`, `Everyone`, `NT AUTHORITY\Authenticated Users` и
   любые учётные записи, кроме вашей. `NT AUTHORITY\SYSTEM` и `BUILTIN\Administrators` обычны для dotfiles, но у целей
   `local/secrets` и `local/backups` лишние (закройте командой из строки `miksy doctor`); под встроенной учётной
   записью «Администратор» они свои — `doctor` о них не пишет.
5. **Вернувшись на новую версию** (`miksy update`; на вопрос о записи настроек можно ответить «да» — копию это не
   трогает) — первый блок (пути), затем верните копию на место:

   ```
   $n = Split-Path $d -Leaf; Get-ChildItem -LiteralPath (Split-Path $d) -Force -Filter "$n-before-miksy-*" | ForEach-Object { [IO.Directory]::Move($_.FullName, (Join-Path $b $_.Name.Substring($n.Length + 1))); "возвращена: $($_.Name.Substring($n.Length + 1))" }
   ```

   Проверка: `miksy doctor` — без «Небезопасные права»; команда шага 3 показывает ссылки копии — они на месте.

На macOS и Linux прежние версии в ссылки не заходят — только команды отката выше.
