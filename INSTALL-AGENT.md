# Установка miksy агентом

Инструкция для AI-агента (Claude Code, Codex, opencode, Antigravity), которому пользователь поручил
поставить miksy. Что такое miksy и как им пользоваться — [README.md](README.md); этот файл — только
порядок установки.

У тебя нет терминала с вопросами: команды miksy без TTY не спрашивают, а делают только безопасную часть
или останавливаются с подсказкой. Все вопросы задаёшь ты — пользователю, в чате.

## Правила

**Сам, без спроса:** проверки (`git`, `bun`, версии), `git clone` движка и конфигурации пользователя,
`setup --yes`, `doctor`, `explain`, `sync … --dry-run`, `adopt … --dry-run`, чтение вывода.

**Только после явного «да» пользователя в чате** (на конкретное действие, которое ты показал):
- обновление движка (`update --yes`; см. «Обновление» в конце);
- установка программ (Bun, Node.js, uv, …);
- правка PATH и профиля оболочки;
- копия настроек агентов (`setup --yes --backup`);
- перенос добавок агентов в конфигурацию (`adopt … --yes`);
- запись настроек агентам (`sync --global`, `sync --all`);
- доверие проекту (`trust <путь> --confirm`; отказ — `--deny`).

**Никогда:**
- не выдумывай и не подставляй секреты; не читай, не выводи и не пересказывай `local/secrets.env`,
  `local/secrets/` и бэкапы в `local/backups/` — там значения;
- не отвечай на вопрос о доверии за пользователя и не обходи его (`--confirm` без «да» в чате);
- не запускай `--force`, `clean`, `target --remove` без прямой просьбы пользователя;
- не правь файлы, которые пишет miksy (`CLAUDE.md`, `AGENTS.md`, конфиги агентов), — правила меняются
  в слоях конфигурации.

Коды выхода: `0` — успех; `1` — ошибка или у `doctor` есть проблемы; `2` — ошибка в аргументах (ничего
не выполнено); `3` — у `sync` были конфликты (эти места не тронуты).

Ниже `<engine>` — каталог движка, `<config>` — конфигурации. Пока команды `miksy` нет в PATH, вместо
`miksy …` запускай `bun "<engine>/src/cli.ts" …`.

## 1. Спроси пользователя

1. **Workspace** — каталог, где лежат его проекты (например, `~/Projects`).
2. **Нужна ли ему та же конфигурация miksy, что на другой его машине** (она в git — тогда адрес репо),
   или новая из примера (другой набор проектов и правил; тогда пункт 3 не нужен).
3. Если есть — **где на первой машине лежали движок и конфигурация** относительно workspace
   (например, `home/Miksy/miksy` и `home/Miksy/miksy-config`). Клонировать нужно туда же: слои
   привязаны к путям («[Вторая машина](README.md#вторая-машина)»). Не знает — клонируй в
   `<workspace>/miksy` и `<workspace>/miksy-config`; шаг 4 предупредит, если раскладка другая.

Сделано: известны workspace, адрес конфигурации (или «нет») и каталог движка.

## 2. Проверь git и Bun

```
git --version
bun --version
```

- git нет — скажи пользователю, как поставить (macOS: `xcode-select --install` или `brew install git`;
  Windows: `winget install Git.Git`), и жди.
- Bun нет или версия ниже 1.3.14 — покажи команду и выполни после «да»:
  - macOS, Linux: `curl -fsSL https://bun.sh/install | bash`, затем в этом же процессе
    `export PATH="$HOME/.bun/bin:$PATH"`;
  - Windows (PowerShell): `powershell -c "irm bun.sh/install.ps1 | iex"`, затем
    `$env:Path = "$HOME\.bun\bin;$env:Path"`.

Сделано: `bun --version` — 1.3.14 или новее.

## 3. Скачай движок (и конфигурацию)

macOS, Linux:

```
mkdir -p "<каталог над движком>"
git clone -b stable https://github.com/wedolab/miksy.git "<engine>"
git clone "<адрес конфигурации>" "<engine>/../miksy-config"      # только если она есть
```

Windows (PowerShell 5.1 — без `&&`):

```
New-Item -ItemType Directory -Force "<каталог над движком>" | Out-Null
git clone -b stable https://github.com/wedolab/miksy.git "<engine>"
git clone "<адрес конфигурации>" "<engine>\..\miksy-config"      # только если она есть
```

Конфигурация — рядом с движком, в `miksy-config`: так её найдёт `setup`. Клон не проходит — проверь сеть;
если адрес — приватная копия, попроси пользователя войти: `gh auth login`, затем `gh auth setup-git`. `-b stable` —
ветка последнего выпуска (с неё работает `miksy update`); если git ответил, что ветки `stable` нет, —
клонируй без `-b stable`.

Сделано: есть `<engine>/src/cli.ts`; если была конфигурация — `<engine>/../miksy-config/map.yaml`.

## 4. Безопасная часть установки

```
bun "<engine>/src/cli.ts" setup --yes
```

Создаёт (если нет): конфигурацию из примера, `local/`, `local/secrets.env` (пустой шаблон),
`local/machine.yaml` (workspace и найденные агенты), команду `miksy` в `~/.bun/bin`. Ничего не пишет
агентам. Прочитай вывод и перескажи пользователю:

- `Workspace: …`, `Агенты: …` — совпадают ли с тем, что он сказал. Workspace не тот или нужен ещё
  агент — после «да» поправь `workspace` / `agents` в `<config>/local/machine.yaml`. Проекты лежат
  ещё где-то (второй диск, облачная папка) — после «да» `miksy root add "<путь>" --tree <Ветка>` (у
  каждого дополнительного корня своя ветка дерева слоёв; [docs/roots.md](docs/roots.md#несколько-корней-workspace); про
  расшаренные облачные папки предупреди пользователя);
- `• Раскладка: …` — движок или конфигурация лежат не там, где их ждут слои. Предложи переложить (п. 3);
  до этого ничего не записывай;
- `Не хватает программ:` — что поставить и какой командой (п. 6);
- `каталог … не в PATH` — нужна правка PATH (п. 6);
- `Не заполнены секреты …` — имена секретов (п. 7);
- `заметка о подготовке машины …` — прочитай этот файл и скажи пользователю, что в нём просят сделать
  руками;
- `команда miksy в PATH — X, а не Y` — на машине уже есть другая команда `miksy` (старая установка):
  скажи пользователю, чью оставить.

`setup --yes` можно запускать повторно (после переноса каталогов, установки программ): сделанное он не
переделывает. `local/machine.yaml уже есть — не трогаю … Найдено сейчас` — это не ошибка, а то, что
он нашёл бы заново.

Сделано: код 0, есть `<config>/local/machine.yaml`.

## 5. Что уже настроено и что будет записано

```
miksy doctor
miksy sync --global --dry-run
miksy sync --all --dry-run
```

`doctor` до первой записи почти всегда возвращает 1 («Не синхронизировано») — это нормально. Покажи
пользователю коротко:

- **«Добавлено агентами в обход слоёв»** — MCP-серверы и skills, которые он добавлял агентам сам. По
  каждому спроси: перенести в конфигурацию (чтобы получили все агенты) или оставить у агента.
  Перенос — п. 6;
- **«Конфликты первого sync»** — его файлы на местах, куда miksy хочет писать; miksy их не тронет;
- план из `--dry-run`: сколько файлов создать и обновить, конфликты, пропущенные серверы
  (`пропущен сервер … — не заданы переменные`), проекты, ждущие решения о доверии;
- **«Глобальные skills не от miksy»**, «Окружение» — справочно, перескажи одной строкой.

Сделано: пользователь видел план и сказал, что делать с каждой добавкой.

## 6. Изменения системы — каждое после «да»

**Копия настроек агентов** (страховка до первой записи; предлагай всегда, если агенты уже настроены):

```
miksy setup --yes --backup
```

Сделано: в выводе `✓ копия: <config>/local/backups/before-miksy-…` или `✓ уже есть: …`. Содержимое
копии не открывай — там значения секретов.

**Программы** — команду бери из вывода `setup --yes` (`установить: …`), выполни, затем
`setup --yes` ещё раз: строки про эту программу больше нет.

**PATH** — чтобы команда `miksy` находилась в новых окнах терминала:

- macOS (zsh): `echo 'export PATH="$HOME/.bun/bin:$PATH"' >> ~/.zshrc` (bash — `~/.bash_profile`);
- Linux (bash): то же в `~/.bashrc`;
- Windows — пользовательский PATH (тип значения сохраняется):

  ```
  $p = (Get-Item HKCU:\Environment).GetValue('Path', '', 'DoNotExpandEnvironmentNames')
  [Microsoft.Win32.Registry]::SetValue('HKEY_CURRENT_USER\Environment', 'Path', ($p.TrimEnd(';') + ';%USERPROFILE%\.bun\bin'), 'ExpandString')
  ```

Сделано: в новом окне терминала `miksy help` работает (проверить может пользователь).

**Перенос добавок агентов** — сначала план, потом запись:

```
miksy adopt --global <имя> --to global --dry-run
miksy adopt --global <имя> --to global --yes
```

Для проекта — `miksy adopt <путь проекта> <имя> --to <уровень>` (уровень: `global`, `workspace` или путь
в дереве, например `Acme`). Ошибка «разные определения» — спроси, чьё взять, и добавь `--agent <id>`.

Сделано: после `adopt` — `doctor` больше не показывает эту добавку в «Добавлено агентами».

## 7. Секреты

Секреты вписывает **пользователь** сам, в файл `<config>/local/secrets.env`, строками `ИМЯ=значение`.
Назови ему путь и имена (из вывода `setup --yes` или `doctor`: «Не заданы переменные»). Значения не
проси прислать в чат, не читай файл и не проверяй его содержимое — проверка только командой:

```
miksy doctor
```

Сделано: в выводе `doctor` нет «Не заданы переменные» (или пользователь решил заполнить позже —
серверы без секрета `sync` пропустит).

## 8. Запись — после «да» на показанный план

```
miksy sync --global
miksy sync --all
```

- `sync --all` без терминала останавливается с кодом 2, если новых проектов больше 10 или workspace
  опасный (домашний каталог, корень диска): покажи список и после «да» повтори с `--yes`.
- **«Нужно решение пользователя о доверии»** — у проекта хуки или свои MCP-серверы в репо команды.
  Покажи пользователю список (что выполнится) и спроси по каждому проекту. «Да» —
  `miksy trust <проект> --confirm`, «нет» — `miksy trust <проект> --deny`. Без ответа — ничего не делай.
- Код 3 и «создан не miksy» — на месте чужой файл. Перескажи; `--force` — только если пользователь сам
  попросит заменить (оригинал miksy сохранит).

Сделано: обе команды завершились с кодом 0 или 3 (конфликты пересказаны).

## 9. Проверка и что сказать пользователю

```
miksy doctor
```

Сделано: «Всё синхронизировано», код 0. Иначе — перескажи разделы вывода и что предлагает сам `doctor`.

Скажи пользователю:

1. Перезапустить открытые сессии агентов (и твою тоже) — настройки читаются при старте.
2. Проверить: открыть любой проект и спросить агента «Процитируй первую строку раздела „## MCP“ в твоих
   инструкциях и вызови context7 для „bun“». Ответ «MCP-серверы подключает miksy по слоям…» и найденная
   библиотека — всё работает.
3. Где лежит копия настроек «до miksy» и как вернуть всё как было — [docs/uninstall.md](docs/uninstall.md).
4. Что-то не так — issue в репо движка с выводом `miksy doctor` (без секретов).

## Обновление

Пользователь просит обновить miksy (или ты проверяешь сам):

```
miksy update --check
```

Ничего не меняет. «У вас последняя версия» — готово. «Есть новая версия» или «ветка разработки» с
«Последний релиз — …» — запусти `miksy update` (без `--yes`): он покажет изменения и остановится.
«Нет доступа к репо» — попроси пользователя войти в GitHub (`gh auth login`, затем `gh auth setup-git`). Перескажи
пользователю записи и **обязательно** — блоки «ВНИМАНИЕ — ломает» и «После обновления нужно». Спроси,
обновлять ли. Только после «да»:

```
miksy update --yes
```

Отказ «незакоммиченные правки» или «ветка разошлась» — перескажи сообщение; не выполняй `stash`,
`checkout -B` и другие команды из него без «да» пользователя. После обновления `update` сам выполнит
безопасную часть `setup`, `doctor` и покажет план `sync` — настройки агентам он без терминала не пишет.
Перескажи план и пункты «После обновления нужно» и после «да» — `miksy sync --global` и
`miksy sync --all` (п. 8). Затем — перезапуск сессий агентов (п. 9).
