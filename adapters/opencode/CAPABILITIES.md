# opencode — возможности и каналы

opencode — агент с CLI (`opencode run`, `opencode mcp list`, `opencode debug config`) и
подключением к редакторам через ACP (проверялся Zed). Конфиги JSON/JSONC: глобальный в
`~/.config/opencode/`, проектные `opencode.json` и `.opencode/`; правила — `AGENTS.md` и
список `instructions`.

Проверено на версиях:

- opencode 1.18.19, 2.0.32, 2.1.4 — Windows 11;
- opencode 1.19.1 — macOS 26.6;
- opencode 1.19.5, затем 2.2.5 — Linux (Ubuntu 24.04; официальный установщик, `~/.opencode/bin`);
- Zed (ACP) — Windows: «OpenCode» из реестра ACP (2.2.5).

miksy пишет настройки в формате **2.x**. `doctor` и мастер `setup` предупреждают, если используется
1.x: версия узнаётся без запуска opencode (2.x при запуске поднимает фоновый сервис) — по пакету npm
(`opencode-ai` — 1.x, `@opencode/cli` — 2.x), каталогу Homebrew (`Cellar/opencode/<версия>`) или, у
официального установщика (`~/.opencode/bin/opencode`), по команде `opencode2` рядом: установщик 2.x
(`opencode.ai/v2/install`) всегда пишет её маленьким скриптом, установщик 1.x (`opencode.ai/install`)
— нет. Установщики проверены по их тексту (2026-11-07).

Источники: документация `opencode.ai/docs` (rules, config) и живые проверки (см. «История
проверок»).

## Возможности и как их использует miksy

«Вживую» — запуск opencode во временных HOME и `XDG_*`: MCP — `opencode mcp list` (без модели),
правила — запрос к бесплатной модели `opencode/big-pickle` (вход не нужен).

| Возможность | Механизм агента (файл/ключ) | Как использует miksy | Проверено |
|---|---|---|---|
| Глобальные правила | `~/.config/opencode/AGENTS.md`; без него — Claude-фолбэк `~/.claude/CLAUDE.md`; `instructions` глобального конфига | Own-файл `~/.config/opencode/AGENTS.md` целиком; `instructions` глобального конфига тоже загрузятся поверх — предупреждение | Вживую: 1.18.19 Windows, 1.19.1 macOS |
| Правила проекта | `AGENTS.md` (обход вверх от cwd; `AGENTS.md` важнее `CLAUDE.md`); `instructions` проектного конфига | Own-файл `.opencode/miksy.md`, подключённый в `instructions` собственного корневого `opencode.json`; командный `AGENTS.md` не трогается | Вживую: 1.18.19 Windows, 1.19.1 macOS; `instructions` глобального и проектного конфигов складываются |
| Skills глобально | `~/.config/opencode/skills/`; также сам читает `~/.claude/skills`, `~/.agents/skills` | Own-файлы `~/.config/opencode/skills/<имя>/`; если skill уже есть в `~/.claude/skills` — предупреждение о дубле | Вживую: 1.18.19 Windows, 1.19.1 macOS |
| Skills проекта | `.agents/skills`, `.claude/skills`, `.opencode/skills`, `.opencode/skill`; `skills.paths` (относительный и абсолютный) | Own-файлы `.opencode/skills/<имя>/`; копия не создаётся, если этот sync доставил skill в `.claude/skills` или `.agents/skills` | Вживую: 1.18.19 Windows, 1.19.1 macOS |
| Импорт командных skills | Командные skills в `.agents/skills`/`.claude/skills` видит сам | Не включён: sync сообщает, сколько командных skills opencode не видит | По коду |
| MCP глобально | `~/.config/opencode/opencode.json[c]` → `mcp` | Merge по именам внутри `mcp`; только строгий JSON | Вживую: 1.18.19 Windows, 1.19.1 macOS |
| MCP проекта | корневой `opencode.json`, `.opencode/opencode.json` (сливаются, `.opencode` грузится позже) | Свой корневой `opencode.json` целиком; корень занят чужим — merge по именам внутри `mcp` | Вживую: 1.18.19 Windows, 1.19.1 macOS |
| Формат сервера | `mcp.<имя>`: `type: "local"\|"remote"`, `command` — массив, `environment` (не `env`), `headers`, `enabled: false` | Пишет форму `mcp.<имя>`; `agents.opencode` слоя может дополнить или выключить (`skip`) | Вживую: 1.18.19 и 2.0.32 Windows, 1.19.1 macOS |
| stdio с секретом | `command` запускает `.cmd`/sh напрямую | `{"type":"local","command":["<local/run/opencode/<цель>/<сервер>-stdio-<хеш>.cmd\|.sh>"]}` | Вживую: 1.18.19 и 2.0.32 Windows (без окон), 1.19.1 macOS |
| HTTP с секретом в заголовке | `{file:путь}` в `headers` — opencode читает файл сам | `"Authorization": "Bearer {file:<local/secrets/ИМЯ>}"`; только для секрета, файл которого создаёт этот sync | Вживую: 1.18.19, 2.0.32, 2.1.4 Windows, 1.19.1 macOS |
| HTTP с секретом в URL | — | Мост `src/bridge.ts` через stdio-обёртку (как у Antigravity) | Вживую: 2.0.32 Windows, 1.19.1 macOS |
| Каталоги-группы | Конфиги и skills родительских каталогов наследуются (одноимённое — ближний) | `inherits: { skills: true, mcp: true }`: каждая цель получает полную цепочку правил, MCP и skills | Вживую: 2.0.32 Windows, 1.19.1 macOS (`test/live/groups.ts`) |
| Реестр проектов | Нет; лог `~/.local/share/opencode/log/opencode.log` пишет каталог каждого запуска | Источник `knownDirs` для `sync --all` | Вживую |

## Куда пишет адаптер

| Что | Глобально (`~`) | Проект |
|---|---|---|
| Правила | `~/.config/opencode/AGENTS.md` (own) | `.opencode/miksy.md` (own) + `"instructions": [".opencode/miksy.md"]` в своём корневом `opencode.json` |
| MCP | `~/.config/opencode/opencode.json[c]` → `mcp` (merge) | свой корневой `opencode.json` (own) или чужой корневой → `mcp` (merge) |
| Skills | `~/.config/opencode/skills/<имя>/` (own) | `.opencode/skills/<имя>/` (own) + `.git/info/exclude` |
| Обёртки секретов | `local/run/opencode/global/` | `local/run/opencode/<проект>-<хеш>/` |

- Шапка сгенерированных файлов: «Сгенерировано miksy (слои: …). Не править вручную —
  изменения вносить в конфигурацию miksy (слои).»
- Свой ли корневой `opencode.json` — решает учёт miksy по каноническому пути, а не содержимое
  файла. Корень свободен — miksy создаёт свой файл (`$schema`, `instructions`, `mcp`), даже
  если есть командный `.opencode/opencode.json`; при совпадении имён серверов тот перекроет
  наш — предупреждение.
- Корень занят чужим конфигом — пишется только `mcp` поимённо, правила не записываются
  (предупреждение). Отслеживаемый git файл — конфликт; чужой файл не скрывается через exclude.
  Серверы с секретами в чужой корневой файл git-проекта не сливаются (конфликт) — выход:
  удалить или переименовать файл, miksy создаст свой.
- JSONC с комментариями и невалидный JSON не сливаются — предупреждение, серверы не
  записываются. Пустой файл (0 байт) считается `{}`. Несколько конфигов в одном каталоге —
  предупреждение.
- Пропущенный сервер (нет переменной) остаётся как был (keep), старая версия сверяется по хешу.
  Исключение — сервер с `{file:}` на отсутствующий файл секрета (`noKeep`): с ним opencode не
  стартует вовсе, поэтому сервер убирается с предупреждением.
- MCP-файлы получают 0600 на macOS/Linux; глобальный `opencode.json` с нашими серверами — и при
  keep единственного сервера, без перезаписи.
- Прежняя лишняя копия skill в `.opencode/skills` удаляется по учёту и хешу, с бэкапом. При
  `sync --agent opencode` (без адаптера, пишущего `.claude/skills`/`.agents/skills`) копия
  нужна; `.codex/skills` opencode не читает и доставкой не считается.
- Захват чужого own-файла сохраняет неротируемый оригинал; `clean` его восстанавливает.

## Различия opencode 1.x и 2.x

| Пункт | 2.0.32 (Windows) | 1.19.1 (macOS) |
|---|---|---|
| `opencode.json` родительских каталогов | всех родителей, и в git-проекте | без git — всех родителей; в git-проекте — до git-корня |
| Относительный `instructions` из унаследованного конфига | только из каталога сессии | без git — все `.opencode/miksy.md` вверх по родителям; в git — свой |
| Абсолютный путь в `instructions` унаследованного конфига | загружается везде | без git — да; в git — нет |
| `AGENTS.md` родителя | только каталог сессии | без git — все родители; в git — нет |
| Skills родителей | все родители, и в git-проекте; ближний перекрывает | без git — родители; в git — свои |
| Одноимённый MCP в группе и ниже | один сервер (ближний) | так же |
| `sync --all` с группами: правила ровно один раз | да (группа, вложенная группа, git-проект) | группа и git-проект — да; вложенная группа без git — правила групп выше дважды |
| Форма `mcp.servers.<имя>` | принимается, в `debug config` так и показывается (1.18.19 на Windows — конфиг невалиден, opencode не стартует) | принимается |
| Фоновый сервис | CLI запускает `opencode serve --service`, который переживает CLI и держит MCP-серверы | не отмечен |
| `debug skill` | нет | есть |

- Поэтому разность слоёв для групп не применяется: в 2.x относительный путь потерял бы правила
  групп, абсолютный задвоил бы их в git-проектах. `exclude` MCP или skill из слоя выше группы не
  действует (придёт из файла группы) — sync предупреждает.
- На 1.x во вложенной группе без git правила групп выше приходят дважды — нужна opencode ≥ 2.0.
- 2.x: первый `mcp list` после старта сервиса бывает пустым, серверы подключаются лениво
  (`pending`); вывод — `✓ имя connected` / `✗ имя failed: …`. Live-скрипты повторяют
  `mcp list` и останавливают сервис песочницы (`opencode service stop`). Ошибку моста opencode
  показывает в `mcp list`.

## Ограничения `{file:}` и обёрток

- Отсутствующий файл в `{file:}` делает невалидным весь конфиг («bad file reference»): не
  работают ни `mcp list`, ни `run`. Поэтому `{file:}` пишется только на файл, созданный этим sync.
- Конечный перевод строки обрезается, кириллица проходит. Длинные значения (1500 байт) и
  значения с `" \ ' & % ! ^` доставляются (2.1.4 Windows).
- Подстановки `${VAR}` нет (только `{env:VAR}`/`{file:path}`): переменные слоя miksy
  подставляет сам, секреты — только обёрткой, `{file:}` или мостом.
- Секрет в `env` HTTP-сервера — пропуск сервера с сообщением; `env` без секретов —
  предупреждение (opencode его не использует).
- stdio-обёртка `.cmd` ставит `chcp 65001`: без него не-ASCII на Windows ломается. Значение
  секрета в обёртке `.cmd` — до 1023 байт; в аргументах и составных переменных — без `"`.
  Файл секрета — одна строка.
- Конфиг не перезагружается на лету — после sync нужен перезапуск сессии.

## Режимы запуска

- CLI на Windows: каталог проекта для `opencode run` берётся из `PWD`, а не из cwd процесса —
  запускать с `PWD` = проект.
- Zed (ACP), Windows: каталог проекта определяется верно; stdio-обёртки `.cmd` (bun, npx)
  запускаются без окон консоли. opencode через ACP видит `AGENTS.md` проекта и глобальные правила
  (2026-11-02).
- Реестр ACP (`agentclientprotocol/registry`): записи «OpenCode» и «OpenCode V2» на 2026-11-02
  одинаковы — обе 2.2.5, одни и те же бинарники (разница — только источник: GitHub или opencode.ai);
  до обновления реестра 2026-10-30 «OpenCode» был 1.x. Сессии 1.x и 2.x лежат в разных таблицах одной
  базы: 1.x на базе, переведённой 2.x, падает («Database is not empty and has no session table»).
- Linux: для `linux-x86_64` реестр даёт обычную сборку, не `-baseline` — на процессоре без AVX2
  opencode через ACP может упасть; тогда своя запись `agent_servers` в Zed, запускающая установленный
  `opencode acp`.

## Не поддерживается

- Agents, commands, permissions, policies, plugins, hooks — открытые вопросы.
- Слияние в JSONC с сохранением комментариев.
- `CLAUDE.local.md` проекта opencode не читает; `.codex/skills`, `.gemini/skills` — тоже.
