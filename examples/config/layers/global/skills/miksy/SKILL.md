# Правила, MCP и skills — только через miksy

У пользователя настройки всех агентов (Claude Code, Codex, opencode, Gemini)
генерирует **miksy** — отдельный репо со слоями. Агенты читают уже
сгенерированные файлы. Поэтому любое правило, MCP-сервер или skill, который
должен жить дольше текущей сессии, добавляется **в слой miksy**, а не в
конфиг агента.

**Нельзя:**
- править сгенерированные файлы (`~/.claude/CLAUDE.md`, `CLAUDE.local.md`,
  `.codex/config.toml`, `opencode.json`, `.agents/plugins/miksy/`, …) —
  правки пропадут при следующей синхронизации;
- добавлять MCP средствами агента (`claude mcp add` и т.п.) — его получит
  только этот агент;
- писать значения секретов в файлы слоёв и в чат.

Работа в конфигурации miksy — разрешённое исключение из правила «не выходить за
пределы проекта», **если пользователь сам попросил** добавить правило, MCP
или skill.

## 1. Уровень

Если пользователь не сказал, спроси, где это нужно:

| Уровень | Где действует | Каталог слоя |
|---|---|---|
| глобально | все агенты везде, личное | `layers/global/` |
| все проекты | весь workspace | `layers/tree/` |
| организация | всё внутри `<workspace>/Org` | `layers/tree/Org/` |
| часть организации / проект | `<workspace>/Org/Team/...` | `layers/tree/Org/Team/...` |

Дерево `layers/tree/` повторяет workspace: имена каталогов — как в workspace
(регистр не важен). Каталога нет — создай.

Пользователь хочет, чтобы правила и MCP работали и в самом каталоге над проектами
(сессия в `<workspace>/Org`, а не в проекте) — это **цель-группа**: `target: true` в
`layers/tree/Org/layer.yaml`, затем `miksy sync --all`. Решает пользователь —
сам не помечай.

**Только для пользователя или для всей команды проекта?** Если skill, правило
или MCP нужны **коллегам** по проекту, место им не в miksy (его видит только
пользователь), а в **репо проекта** — с коммитом, по просьбе пользователя:
- skill — туда, где в репо уже лежат skills команды; если таких нет —
  `.agents/skills/<имя>/SKILL.md` (общий формат, его читают несколько агентов);
- правило — в командный `AGENTS.md` / `CLAUDE.md` проекта;
- MCP — в командный конфиг проекта (`.mcp.json` и т.п.), без секретов.

Miksy сам доставит командные skills агентам пользователя, которые их не видят.
Если непонятно, для кого это, — спроси: «только для вас или для всей команды?»

## 2. Где конфигурация miksy и какие слои у проекта

```
miksy explain .
```

Строка «Конфигурация» — каталог со слоями на этой машине (обычно `miksy-config`
рядом с движком), ниже — слои текущего
проекта. Если команды `miksy` нет — `bun src/cli.ts …` из каталога репо.

## 3. Что и куда положить

**Правило** — markdown в `<слой>/instructions/<NN>-<тема>.md` (файлы
склеиваются по имени, `NN` задаёт порядок). Каталоги `hooks/` и `policies/` в слое
miksy не читает — хуки и права агентов через miksy не настраиваются.

**MCP-сервер** — `<слой>/mcp/<имя>.yaml`:

```yaml
name: gitlab
command: npx
args: [-y, "@zereight/mcp-gitlab"]
env:
  GITLAB_PERSONAL_ACCESS_TOKEN: ${ORG_GITLAB_TOKEN}   # секрет — только ссылкой
  GITLAB_API_URL: https://gitlab.example.com/api/v4
```

Удалённый сервер: `url:` и при необходимости `headers:`
(`Authorization: Bearer ${ORG_SERVICE_TOKEN}`). Пути машины — через
`${WORKSPACE}`, `${HOME}` или переменные из `local/machine.yaml`.
Не подключать конкретному агенту: `agents: { gemini: skip }`.

Значение секрета пользователь кладёт в `local/secrets.env` конфигурации miksy
(`ORG_GITLAB_TOKEN=…`). Если он дал значение тебе — запиши туда сам, но не
повторяй его в ответе.

**Skill** — `<слой>/skills/<префикс><имя>/SKILL.md` с frontmatter `name` и
`description` (по `description` агент решает, когда skill нужен). Префикс — из
`skill_prefix` в `map.yaml` конфигурации (по умолчанию `miksy-`): так skill не совпадёт с
командными skills в репо проектов.

## 4. Применить

```
miksy sync --all        # слои tree
miksy sync --global     # если меняли layers/global
miksy doctor            # проверить, что всё сошлось
```

Скажи пользователю перезапустить сессии агентов — конфиги читаются при старте.

Изменения в конфигурации miksy (это отдельный git-репо) **не коммить** без просьбы — предложи коммит.

## Доверие проектов — решает только пользователь

Если `miksy sync` или `miksy doctor` выводит «Нужно решение пользователя о
доверии» (в проекте хуки, разрешения, `.mcp.json` или конфиг Codex не от miksy —
закоммиченные командой или неотслеживаемые; с доверием агент выполнит их без вопроса):

- **не подтверждай доверие сам** и не запускай `miksy trust … --confirm` по своей
  инициативе;
- покажи пользователю список из вывода (что будет выполняться) и пути файлов из строки
  «полное содержимое — в файлах» (скрытые значения он может посмотреть там) и спроси,
  доверять ли;
- лучше всего — предложи ему выполнить `miksy trust <проект>` в терминале;
- только после явного «да» пользователя в чате — `miksy trust <проект> --confirm`
  (тот проект и агент, о котором спросил: `--agent claude|codex`); «нет» —
  `miksy trust <проект> --deny`.

То же — для **серверов командного `.mcp.json`** (Claude включает их только после
одобрения; в списке — «серверы .mcp.json (Claude)» с их командами): одобряет только
пользователь, тем же `miksy trust <проект>` (`--confirm` — только после его «да»).
Не правь сам `enabledMcpjsonServers`/`disabledMcpjsonServers` в
`.claude/settings.local.json` проекта и не ставь `enableAllProjectMcpServers`.

Не ставь `trust: true` в слои и не правь `local/trust.json` без прямой просьбы
пользователя.

## Если уже добавлено в обход слоёв

Если MCP или skill уже создан средствами агента в каком-то проекте, его не
нужно переписывать вручную:

```
miksy doctor                                         # покажет такие добавки
miksy adopt <путь проекта> <имя> --to <уровень>      # поднять в слой
miksy adopt --global <имя> --to <уровень>            # из глобальных настроек агента
miksy sync --all
```

`<уровень>` — `global`, `workspace` или путь в дереве (`Org`, `Org/Team`).
`adopt` сам выносит токены в `local/secrets.env` и пути машины в переменные.
Если `sync` после этого сообщит конфликт с исходной записью агента —
`miksy sync <проект> --agent <агент> --force` (с бэкапом).

Подробности — `README.md` движка miksy.
