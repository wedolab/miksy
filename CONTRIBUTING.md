# Как участвовать

Спасибо, что хотите помочь. Что такое miksy — [README.md](README.md), как он устроен —
[DESIGN.md](DESIGN.md). Ошибки и предложения — через [issue](https://github.com/wedolab/miksy/issues/new/choose);
уязвимости — не в issue, а по [SECURITY.md](SECURITY.md).

## Движок для разработки

Нужны git и [Bun](https://bun.sh) 1.3.14 или новее. Зависимостей нет — `bun install` не нужен.

```
git clone https://github.com/wedolab/miksy.git
cd miksy
bun test
```

Разработка — в ветке `main` (или своей ветке от неё); `stable` — последний выпуск для пользователей,
её двигает только выпуск ([RELEASING.md](RELEASING.md)). Запускать свою копию — `bun src/cli.ts …`.

## Тесты

- `bun test` — весь набор; перед изменением поведения — тест, который без изменения падает.
- Тесты работают в песочнице (`test/preload.ts`): свой HOME, tmp и конфигурация. `test/guard.ts`
  останавливает прогон (код 97), если тест запускает команду miksy с записью (`sync`, `setup`,
  `update` и т. д.) в настоящем окружении. Не ослабляйте эту защиту; новая команда, которая пишет, —
  в её список.
- Проверяйте на Windows и на macOS или Linux: пути, права, переводы строк и оболочки там разные.
- Живые проверки с настоящими агентами — `test/*-live.ts` и `test/live/` (запускаются вручную).

## Изменения

- Коммит — одно законченное изменение; заголовок в повелительном наклонении, до 50 символов
  (`Strip BOM from SKILL.md on delivery`).
- Изменение, которое заметит пользователь (или ему нужно что-то сделать), — строка в разделе
  «Не выпущено» `CHANGELOG.md` **в том же коммите**: «Новое», «Исправлено», «Ломает», «После
  обновления». Тесты, рефакторинг, опечатки — без строки. Подробно — [RELEASING.md](RELEASING.md).
- Новое сообщение для пользователя — строка в таблице «Если что-то пошло не так» README; устройство —
  в DESIGN.
- Секреты, личные пути и данные — никогда в коде, тестах и issue.
